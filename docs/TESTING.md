# TESTING

## 실행
```bash
node tests/run.mjs            # 1회
node tests/run.mjs 10         # 10회 반복 (플레이키 검출)
node tests/run.mjs 3 "조명"   # 이름에 "조명" 이 든 항목만 3회
node tools/codemap.mjs        # docs/CODEMAP.md 다시 생성
node tools/tidy-imports.mjs   # 안 쓰는 import 정리
```
실패가 있으면 종료 코드 1.

## 구성
- `tests/harness.mjs` — 정적 서버 + 브라우저 기동 · 게임 로드 대기 · `assert` / `eq` / `near`
  ES 모듈은 `file://` 에서 CORS 로 막히므로 **임시 HTTP 서버**를 띄워 그 위에서 돌립니다.
- `tests/run.mjs` — 테스트 정의 + 러너 + 회차별 요약
- 브라우저: `playwright-core` + 로컬에 캐시된 **Chrome for Testing**
  (`~/Library/Caches/ms-playwright/chromium-1228/...`), WebGL 은 SwiftShader.
  경로는 환경변수 `BY_CHROME` 로 바꿀 수 있습니다.
  `playwright-core` 는 스크래치패드에 설치돼 있고 `BY_SCRATCH` 로 위치를 바꿀 수 있습니다.

## 규칙
1. **회차마다 페이지를 새로 엽니다.** 테스트끼리 월드 상태가 새는 것은 감수하되,
   지형에 의존하는 테스트는 `arena(B, x, y, z, r)` 로 **평평한 시험장을 직접 만들어** 씁니다.
   (지형에 기대면 앞선 테스트의 `generate(시드)` 때문에 무작위로 깨집니다 — 실제로 겪었습니다.)
2. **콘솔 오류 0** 자체가 하나의 테스트입니다. `pageerror` · `console.error` 를 전부 모읍니다.
3. 결정적인 결과가 필요하면 `B.setPaused(true)` 로 rAF 루프를 멈추고
   `B.step(1/60)` 을 직접 돌립니다. 끝나면 `setPaused(false)`.
4. 입력은 `B.setKey("KeyW", true)` 로 넣고, 실제 이벤트 경로를 검증할 때만
   `dispatchEvent(new MouseEvent(...))` 를 씁니다.
5. **새 기능에는 테스트를 같이 넣습니다.** 이름은 `개선N ...` 처럼 무엇을 지키는지 드러나게.
