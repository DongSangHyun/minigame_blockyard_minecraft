# DECISIONS — 왜 이렇게 만들었나

새 세션이 "이거 왜 이렇게 돼 있지?" 하고 되돌리는 일을 막기 위한 기록입니다.

## D1. 빌드 단계를 만들지 않는다
저장소를 그대로 정적 호스팅에 올리면 도는 상태를 유지합니다.
번들러가 생기는 순간 "링크 하나로 열리는 게임" 이라는 성질과 배포의 단순함을 잃습니다.
ES 모듈은 브라우저가 직접 읽으므로 이 원칙을 깨지 않습니다.

> 원래는 "파일 하나로 유지한다" 였습니다. 2026-09-05 사용자가 이 제약을 풀었고,
> 4,000줄이 한 파일에 있던 것을 모듈 24개로 나눴습니다 (D15).

## D2. 텍스처를 코드로 그린다
`paint(타일번호, 함수)` 로 16×16 도트를 캔버스에 직접 찍습니다.
이미지 파일이 0개라서 파일 하나 규칙(D1)이 유지되고, 색을 바꾸는 것이 상수 수정으로 끝납니다.

## D3. ES5 문체
기존 3,500줄이 전부 `var` + `function` 입니다.
문체를 섞으면 "이 부분은 새로 쓴 것"이라는 무의미한 경계가 생깁니다. 통일이 가독성보다 우선입니다.

## D4. 조명은 편집 시 국소 재계산
전역 재계산(`relightAll`)은 44만 셀을 훑기 때문에 편집마다 돌릴 수 없습니다.
`relightLocal` 이 BFS 로 지운 뒤 다시 퍼뜨리고, 전역 재계산은 `relightSoon()` 으로 예약될 때만 돕니다.

## D5. 청크 굽기는 프레임 예산제
`buildBudget(8)` — 한 프레임에 8ms 넘게 굽지 않습니다.
"한 번에 다 굽고 렉" 대신 "몇 프레임에 걸쳐 나타남"을 택했습니다. 첫 화면만 예외로 70ms.

## D6. 크리에이티브 모드다 (체력·인벤토리 없음)
무한 블록 · 비행 · 낙하 피해 없음. 그래서 **캐기 속도는 굳기 기반**으로 남겨 뒀습니다
— 크리에이티브의 즉시 파괴는 편하지만 채굴의 촉감이 사라지기 때문입니다.

## D7. Shift 는 웅크리기다 (v5)
원래 Shift = 달리기였습니다. 마크를 오래 한 사람은 **공중 다리 위에서 습관적으로 Shift 를 누릅니다.**
그때 더 빨리 달려서 추락하면, 그 한 번으로 "이 게임은 마크가 아니다"가 각인됩니다.
달리기는 마크와 같이 `Ctrl` 과 `W` 더블탭으로 옮겼습니다.

## D8. 스텝 높이는 0.6 이다 (v5)
1.05 였을 때는 1블록 벽을 걸어서 통과했습니다. 그러면
(a) 지형을 오를 때 점프를 안 하게 되어 이동의 박자가 사라지고,
(b) 애써 만든 반블록·계단이 "굳이 안 만들어도 되는 장식"이 됩니다.
0.6 은 마크와 같은 값이고, 반블록·계단은 여전히 걸어서 오릅니다.

**주의:** 스텝업은 "요청한 이동량의 90% 이상을 실제로 통과했을 때"만 인정합니다.
그렇지 않으면 벽에 붙은 채로 0.6칸 공짜 상승이 일어납니다 (v5 에서 잡은 버그).

## D9. 이동에 관성을 넣었다 (v5)
이전에는 입력을 그대로 위치 변화로 썼습니다(`moveHorizontal(mx*dt, ...)`).
지금은 `player.vel.x/z` 를 목표 속도로 붙이고(`grab`), 입력이 없으면 마찰로 줄입니다.
공중에서는 가속을 24%로 줄여, 점프 중에는 방향을 거의 못 바꿉니다 — 마크 점프 아치의 정체성입니다.
`moveAxis` 가 충돌 시 해당 축 속도를 0으로 만들기 때문에, 벽에 부딪히면 관성도 함께 끊깁니다.

## D10. 비는 하늘이 뚫린 칸에만 그린다 (v5)
파티클을 지우지 않고 **그리기 좌표만** `HIDE_Y(-900)` 로 치웁니다(`wDraw` / `rPos`).
시뮬레이션 좌표(`wPos`)는 그대로 두기 때문에, 집에서 나오면 비가 즉시 다시 보입니다.
판정은 `columnTop()` — `topMap` 을 그대로 쓰므로 비용이 사실상 0 입니다.

## D11. 광석은 씨앗 랜덤워크로 자란다 (v5)
칸마다 독립 확률로 뿌리면 인접한 광석 2개를 볼 확률이 사실상 0 이고,
"하나 찾으면 주변을 파헤친다"는 채굴의 보상 곡선이 통째로 사라집니다.
총 광석량은 이전과 비슷하게 유지하면서 뭉치기만 했습니다 (`veinTries = WX*WZ*0.055`).

## D12. 기반암은 블록으로 만든다 (v5)
이전에도 `y === 0` 은 `applyEdit` 이 막고 있었지만 텍스처가 STONE 이라
**캐다가 갑자기 안 캐지는 버그처럼** 보였습니다. 눈으로 "여기가 끝"임을 알려 주는 것이 요점입니다.
`isUnbreakable()` 로 분리했으므로 앞으로 y 와 무관하게 캘 수 없는 블록을 추가할 수 있습니다.

## D13. 파괴적 조작에는 확인을 건다 (v5)
`R` 한 번에 세계가 통째로 재생성되고 있었습니다. 안내에도 없는 키였습니다.
지금은 첫 번째 R 이 토스트만 띄우고, 2.2초 안에 한 번 더 눌러야 실행됩니다.

## D14. 테스트는 실제 브라우저에서 돈다
WebGL·캔버스·localStorage·이벤트를 흉내 내는 대신 진짜 Chrome(SwiftShader)을 띄웁니다.
`window.__blockyard` 훅이 그 접점입니다 — **새 기능은 반드시 여기에 노출**해야 합니다.
`setPaused(true)` 로 rAF 루프를 멈추면 결정적으로 테스트할 수 있습니다.

## D15. ES 모듈로 나눈 방식 (2026-09-05)
4,000줄짜리 IIFE 하나를 `src/` 아래 24개 모듈로 나눴습니다.
겉보기 동작은 하나도 바뀌지 않았고, 회귀 테스트 50항목이 전후 모두 통과합니다.

**세 가지 규칙으로 정리했습니다.**

1. **읽기는 `import`, 쓰기는 `S`.**
   ES 모듈에서 import 한 바인딩은 읽기 전용이라 대입하면 `Assignment to constant variable` 이 납니다.
   그래서 **여러 모듈이 값을 바꾸는 변수만** `src/state.js` 의 `S` 객체로 모았습니다(71개).
   한 모듈만 쓰는 값은 그냥 `export var` 로 두고, 다른 모듈은 라이브 바인딩으로 읽습니다.
   이 구분 덕분에 "누가 이 값을 바꾸는가" 가 파일에 드러납니다.

2. **뿌리 모듈은 아무것도 import 하지 않는다** — `state.js` · `dims.js` · `queues.js`.
   ES 모듈은 import 그래프 순서로 평가되므로, 순환이 있으면 어떤 모듈이
   **아직 값이 채워지지 않은** 다른 모듈을 최상위에서 읽게 됩니다.
   실제로 `atlas → audio → … → hand → atlas` 순환 때문에 `tileOrigin` 이 `undefined` 인 채로
   기하를 만들다 터졌습니다. 치수와 큐를 의존성 없는 뿌리로 빼서 이 부류를 없앴습니다.

3. **순환이 남는 곳은 함수 호출 시점에만 서로를 본다.**
   `world ↔ fluids`, `light ↔ mesh` 처럼 서로 부르는 관계는 남아 있지만,
   최상위에서는 상대의 값을 읽지 않으므로 안전합니다.
   `waterLvl` 은 원래 `fluids` 에 있었지만 세계 데이터이므로 `world` 로 옮겨 순환 하나를 없앴습니다.

**분리 도구는 남기지 않았습니다.** 자동 분리 스크립트를 저장소에 두면
"단일 파일" 과 "모듈" 두 개의 진실이 생기고, 다음 세션이 어느 쪽을 고쳐야 할지 헷갈립니다.
지금부터 진실은 `src/` 하나입니다. 분리 전 원본은 git 이력에 있습니다.

## D16. 모바일을 1급으로 다룬다 (2026-09-05)
GitHub Pages 에 올린 순간 **첫 접속의 상당수가 폰**입니다. 그래서:
- viewport 메타가 없으면 페이지가 980px 로 렌더돼 터치 UI 좌표가 통째로 어긋납니다. 가장 먼저 고칠 것.
- 렌더 해상도는 터치 기기에서 **1.25 로 묶습니다.** DPR 3 인 폰에서 2배로 그리면
  44만 셀 월드에서 프레임이 무너집니다. 시야거리도 120 → 72 로 낮춥니다.
- HUD·핫바는 좁은 화면에서 줄이고, 노치는 `env(safe-area-inset-*)` 로 피합니다.
- 세로로 들면 게임을 그리지 않고 "가로로 돌려 주세요" 를 띄웁니다. 세로 복셀 샌드박스는 쓸 수 없습니다.

## D17. 갇힘은 게임이 스스로 풀어 준다 (2026-09-06)
복셀 세계에서 몸이 블록과 겹치는 일은 **반드시 일어납니다** — 물이 얼고, 모래가 내려앉고,
저장한 자리에 지형이 바뀌고, 이동이 한 칸을 뛰어넘습니다. 겹치는 순간 `moveAxis` 는
모든 방향을 막으므로 플레이어에게는 되돌릴 수단이 아예 없습니다(비행조차 소용없습니다).
그래서 원인을 하나씩 막는 대신 **결과를 항상 푸는 쪽**을 택했습니다: `unstick()` 이 매 프레임
겹침을 확인하고 가장 가까운 빈 자리로 밀어냅니다. 원인 차단(얼음 가두기 방지 등)은
그 위에 얹는 예방책이지, 유일한 방어선이 아닙니다.
